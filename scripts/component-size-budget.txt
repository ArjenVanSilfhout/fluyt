# Fluyt component size budgets
#
# WHAT THIS IS: the per-file byte budgets check [12] in scripts/validate-local.ps1 enforces for
# every Markdown file directly in a shipped skill directory (plugins/*/skills/*/*.md - SKILL.md plus
# the reference files a skill splits out, in scope; a skill's templates/ subdirectory is
# one level deeper and NOT budgeted) and every canonical role (plugins/*/agents/*.md). Every lane
# that loads one of these files pays for ALL of it on EVERY load, and without a cap, files regrow
# silently. This is a RATCHET, not a target: it stops silent growth; it does not demand a trim.
#
# THE FORMULA (DECISIONS.md, 2026-10-11): a file's budget is its current
# measured size x 1.05, rounded UP to the next 100 bytes - i.e. ceil(size * 1.05 / 100) * 100.
# "Measured size" is the UTF-8 byte count of the file with CR (0x0D) bytes excluded, so a Windows
# checkout and Linux CI measure the same number (see the [12] comment in the script).
#
# THE MAINTENANCE RULE:
#   - RAISING a line is a DELIBERATE act. A file that outgrows its budget fails the gate; the
#     remedies are to trim it, or to raise its line here - and the reason for the raise goes in
#     the PR. Re-apply the formula to the new size; do not round generously.
#   - LOWERING follows when a file shrinks: the gate WARNs (non-blocking) when a budget sits above
#     the formula's value for the file's current size, and names the number to set. Take it - that
#     is what makes this a ratchet.
#   - A NEW skill, skill reference file or agent needs its own line here: the gate FAILs on an
#     in-scope file with no budget. A removed or renamed file's line must go too: the gate FAILs on
#     a stale line.
#
# FORMAT: one entry per line, '<repo-relative path, forward slashes> <budget in bytes>', separated
# by whitespace. Blank lines and lines starting with '#' are ignored. Paths are matched exactly and
# case-sensitively; a path may appear only once. Keep entries sorted by path and ASCII-only (this
# file is read on PowerShell 5.1 hosts too - see plugin-vocabulary-allowlist.txt's ENCODING note).
