# Fluyt plugin-vocabulary allowlist
#
# WHAT THIS IS: the single source of truth for the HEURISTIC half of check [7] in
# scripts/validate-local.ps1 - the inverted forbidden-strings guard that mechanically enforces
# CLAUDE.md's "Zero project facts in plugins/" invariant. That half does not enumerate known-bad
# tokens (a denylist cannot know which consumers exist). It flags EVERYTHING under plugins/ that is
# project-fact-SHAPED - slug-shaped identifiers, framework / runtime / build-tool names, absolute
# and drive-letter paths - and then subtracts the lines below. Every entry here is a token that
# looks like a project fact but is legitimately the PLUGIN'S OWN vocabulary.
#
# THE MAINTENANCE TRIGGER IS THE POINT: this file is maintained when the PLUGIN'S OWN VOCABULARY
# CHANGES - a new agent-client tool name, a new shipped snippet, a new product the plugin has to
# name by name. That is a moment the maintainer is already in these files, with the gate red in
# front of them telling them the exact token. It is deliberately NOT maintained when a third party
# adopts the plugin: that moment is unobserved, so an enumerated-consumers list cannot stay
# current. A forgotten entry here shows up as a RED gate on the next run.
#
# WHAT MUST NEVER GO HERE: a consumer's project name, repo slug, or stack token. When check [7]
# flags one of those, the fix is to REMOVE THE FACT from plugins/ - never to allowlist it. The one
# category that looks like a violation and is not is the plugin naming ITSELF: CLAUDE.md's
# sanctioned-self-reference test ("names the plugin's OWN identity or home - its slug, its repo,
# its author, its manifest metadata - never a consumer fact") is why 'Fluyt' and
# 'ArjenVanSilfhout' are listed below rather than scrubbed. If you are about to add an entry and
# cannot say which of the sections below it belongs to, that is the signal to stop and check
# whether it is really the plugin's vocabulary at all.
#
# FORMAT: one token per line. Blank lines and lines starting with '#' are ignored - everything else
# is taken verbatim (trimmed) as a token. Matching is WHOLE-FINDING and case-INsensitive: an entry
# exempts a finding only when it equals that finding's matched text, so 'GitHub' exempts the word
# GitHub and does NOT exempt 'GitHubSomethingElse' (which the heuristic reports as its own,
# separate finding). Case-insensitivity is deliberate - a token differing from legitimate plugin
# vocabulary only in letter case is not a distinct project fact worth reddening the gate for.
#
# ENCODING: keep every entry ASCII-only - check [7] reads
# plugins/ content as UTF-8 explicitly, but this file is read as plain text on a PowerShell 5.1
# host, where Get-Content's default codepage is not UTF-8.
